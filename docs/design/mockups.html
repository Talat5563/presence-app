Bidirectional rules and iOS divergence

RTL — the rules every screen follows
Mirror the layout, not the content. Rows, gutters, list chevrons, back arrows, progress fills and slider direction all flip. Photos, faces, the app mark, waveforms and media controls never flip — a mirrored waveform reads as a different sound.
Every name is a bdi. Names, user-typed text and numbers are isolated and get their font stack from the string's own script, not the UI language. That is what keeps ‪מאיה might be calling you‬ from scrambling.
Never concatenate. One localised sentence with one named placeholder per string, so the Hebrew writer controls word order. No "{name}" + " might be calling you".
Neither language may set the width. Hebrew runs shorter here; buttons and cards size to content with a minimum, and no layout depends on a line count. Headlines use text-wrap:pretty and are checked at both lengths.
Hebrew line-height is +0.15. The only per-script metric change: 1.55 becomes 1.70 for body. Type sizes are identical; Hebrew is never bumped up to compensate for having no capitals.
The overlay is the riskiest screen. It is centre-aligned by design, so it survives mirroring almost unchanged — that was a deliberate choice, not luck. The two buttons stack rather than sit side by side, so their order doesn't flip and muscle memory holds across languages.
Hebrew copy is written, not translated. Every emotionally weighted string in strings.json carries an intent note so a native writer can reach for the feeling rather than the words. The Hebrew in these mockups is a placeholder for that pass, not the shipping copy.
